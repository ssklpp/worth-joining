# 006. 첫 화면은 지도 + 패널(목록 · 상세 · 비교)

| 항목 | 내용 |
|---|---|
| 상태 | 채택 · 2026-10-13. [005](./005-웹-첫-화면과-결과표.md)의 1번(첫 화면은 검색)을 대체한다. 2번(결과표 3행)은 그대로 |
| 관련 | SPEC 9장, [03_ui_design.md](../03_ui_design.md) 5장, 시안 [map-home.html](../mockups/map-home.html), [06_architecture.md](../06_architecture.md) R5, docs/05 3장 `rep_location` |

## 배경

005는 회사 좌표가 없던 Phase 6에 검색을 첫 화면으로 두고, 지도 메인은 Phase 8에서 다시 판단하기로 했다. Phase 8에서 `company_location`(DART 본사 · 상호 검색, 11,961곳)과 `/map/companies`가 생겼고, 검색 · 상세 · 지도 · 비교가 서로 다른 화면으로 나뉘어 있었다.

## 결정

1. **첫 화면은 지도와 왼쪽 패널이다(docs/03 5장 시안).** 패널은 목록 → 상세 → 비교로 바뀌고, 지도는 그대로 남는다.
2. **경로는 그대로 둔다.** `/`(목록), `/?q=`(검색 결과), `/companies/[id]`(상세), `/compare`(비교)가 모두 `web/app/(explore)/layout.tsx` 아래에 있어 같은 지도를 공유한다. 링크 공유와 뒤로 가기는 지금처럼 된다. `/map`은 `/`로 보낸다.
3. **검색은 지도와 관계없이 전체 회사에서 찾는다.** 좌표가 있는 회사는 9.5%(가입자 1,000명 이상은 77.6%, docs/validation.md)뿐이라, 지도 범위로만 찾으면 대부분의 회사를 찾을 수 없다. 위치가 없는 회사의 상세는 "지도에 위치가 없는 회사입니다"라고 쓴다.
4. 상세를 열면 `rep_location`으로 지도를 그 회사로 옮기고 핀을 채운다. 같은 좌표의 핀(같은 건물)을 누르면 목록을 그 회사들로 좁힌다.

## 이유

- 회사를 지도 위에서 주변 회사와 함께 보는 것이 이 서비스가 검색 사이트와 다른 점이다(docs/03 5장).
- 라우트 그룹 레이아웃은 경로가 바뀌어도 다시 그려지지 않으므로, 패널을 바꿔도 지도를 다시 불러오지 않는다.
- 상세 구획(결과표, 추이, 재무)은 005에서 컴포넌트로 만들어 두어 패널로 그대로 옮겼다. 패널 폭에 맞추려고 `@media` 대신 `@container`를 쓴다.

## 하지 않은 것

1km 원 · 근처 역(역 데이터, Phase 9), 공고 수 지표 · 채용 중 필터(사람인, Phase 10), 핀 팝업 미니 그래프(P2).

## 영향

- SPEC 9장 화면표, docs/03 5장, docs/06 R5를 고친다.
- 좌표가 없는 회사가 많아 지도에는 큰 회사 위주로 보인다. 도로 · 동 중심 좌표(decisions/004 3 · 4단계)가 들어오면 나아진다.
