# 005. 웹 첫 화면은 검색, 회사 지표는 결과표 행 3개

| 항목 | 내용 |
|---|---|
| 상태 | 채택 · 2026-10-12 |
| 관련 | SPEC 9장 · Phase 6, [03_ui_design.md](../03_ui_design.md) 1 · 5장, [06_architecture.md](../06_architecture.md) R5 |

## 배경

docs/03 시안은 지도가 첫 화면이고 회사 상세를 지도 옆 패널에서 여는 구조다. SPEC 9장은 검색(`/`)을 첫 화면, 지도를 `/map`으로 둔다. 또 SPEC 9장은 회사 상세의 지표를 "체력 카드 3개"로, docs/03은 "결과표의 행 3개"로 그린다. 두 문서 모두 "팀장이 판단한다"로 남겨 두었다.

Phase 6 시작 시점에는 회사 좌표(`company_location`, decisions/004)가 없다. 좌표는 Phase 8에서 만든다.

## 결정

1. **첫 화면은 검색이다(SPEC 9장 그대로).** `/`는 검색, 회사 상세는 `/companies/[id]` 단독 화면이다. 지도는 Phase 8에서 `/map`으로 추가하고, 그때 지도를 첫 화면으로 바꿀지 다시 판단한다(R5는 그때까지 보류).
2. **회사 지표 3개(성장 · 안정 · 연봉)는 결과표의 행 3개로 그린다(docs/03).** 행마다 측정값, 업종 기준 범위 막대(p25 ~ p75, 중간값, 회사 점), 판정 문장을 둔다. SPEC 9장의 "체력 카드 3개"를 "결과표 3행"으로 고친다.

## 이유

- 지도 메인은 좌표가 있어야 쓸 수 있다. 지금 지도를 첫 화면으로 두면 빈 지도로 시작하거나 Phase 8을 앞당겨야 한다.
- 상세 화면의 구획(결과표, 추이, 입퇴사 표, 재무)을 컴포넌트로 만들어 두면, 나중에 지도 패널로 옮겨도 그대로 쓸 수 있다.
- 카드를 나란히 두면 업종 범위와 회사 값을 같은 축에서 비교하기 어렵다(docs/03 1장).

## 영향

- SPEC 9장 회사 상세 구성 문구 수정.
- docs/06 R5는 "Phase 8에서 다시 판단"으로 바꾼다.
