# 003. 국민연금 적재의 탈퇴 행 처리 · 품질 검사 · 자연키 중복 합산

| 항목 | 내용 |
|---|---|
| 상태 | 채택 · 2026-10-12 |
| 관련 | SPEC Phase 2-3 · 2-4, FR-DATA-03, T1-04, T2-01, T2-02, [profiling.md](../profiling.md) P1 · P2 |
| 근거 데이터 | 서울 2025-08 ~ 2026-08 13개월 |

## 배경

- **P1:** SPEC 품질 검사 "`members ≤ 0`이면 `failed`"를 행 단위로 적용하면 13개월이 **모두 실패**한다. 파일마다 탈퇴(`status_code=2`) 사업장 약 6천 행이 0명으로 들어 있기 때문이다.
- **P2:** 사업장 자연키(회사 + 사업장명 + 법정동)가 같은 행이 매달 86~95행 있다. 그대로 UPSERT하면 한 행이 다른 행을 덮어써 가입자가 사라진다.

### 탈퇴 행 분석 (2026-08)

| 구분 | 행 | 상실자 합 | 해석 |
|---|---|---|---|
| 전월 등록 → 이번 달 탈퇴 | 152 | 422 | 전월 가입자 907명. **실제 퇴사가 기록된 행**이라 버리면 퇴사율이 낮아진다 |
| 전월에도 탈퇴 | 235 | 1 | 이미 끝난 사업장이 남아 있는 행 |
| 전월에 없던 키 | 5,697 | 1,348 | 이전 11개월 중 같은 키로 본 적 있는 것은 863개뿐. 같은 회사(biz_no6 + name_norm)가 전월에 있던 경우는 3개. 탈퇴 시점에만 목록에 나타나는 사업장으로 보인다 |

그래서 탈퇴 행을 모두 버리면 실제 퇴사를 잃고, 모두 넣으면 가입자 0명짜리 회사가 매달 수천 개 생긴다.

## 결정

### 1. 탈퇴 행 처리 (P1)

- `raw_nps_workplace`에는 모든 행을 그대로 보존한다(3계층 원칙).
- `company` · `workplace`는 **등록(`status_code=1`) 행에서만 만든다.** 탈퇴 행만 있는 사업장은 회사로 만들지 않는다.
- `workplace_monthly`에는 등록 행과, **전월에 가입자가 있던(`members > 0`) 사업장의 탈퇴 행**을 넣는다. 탈퇴한 달의 상실자가 회사 퇴사율에 들어간다.
  - 2026-10-12 구현 중 보완: 처음에는 "이미 `workplace`에 있는 사업장의 탈퇴 행"이었는데, 이미 탈퇴한 사업장의 행이 다음 달에도 남아 있어(2026-08에 235행) 0명 행이 매달 쌓인다. 전월 가입자 조건으로 탈퇴한 그 달만 넣는다. 그래서 **월은 오름차순으로 적재해야 한다.**
- 탈퇴 행의 `left_on`으로 `workplace.left_on`을 갱신한다. 값이 비어 있으면 기존 값을 유지하고, 다시 등록되면 `NULL`로 되돌린다.

### 2. 품질 검사 (P1)

실패하면 `ingestion_log.status='failed'`로 남기고 mart를 갱신하지 않는다.

| 검사 | 기준 | 13개월 실제 값 |
|---|---|---|
| 행 수 변동 | `raw_nps_workplace` 해당 월 행 수가 전월 대비 ±10% 초과 | 최대 ±1.2% |
| 가입자 0 이하 | **등록 행 중** `members ≤ 0` 비율이 **1% 초과** | 최대 0.112% (2026-07) |
| 고지금액 상한 | 등록 행 중 `billed_amount > members × income_cap × rate`인 행이 1건 이상 | 0건 |
| 기준표 범위 | 적재 월이 `nps_rate` 기간 밖 (04 문서 D2) | 13개월 모두 범위 안 |

- 기존 규칙(행 하나라도 `members ≤ 0`이면 실패): 13개월 **모두 실패**
- 새 규칙: 13개월 **모두 통과**

1%는 정상 월 최댓값(0.112%)의 약 9배다. 공단 파일이 깨져 가입자 수가 대량으로 0이 되는 경우를 잡는 것이 목적이다.

### 3. 자연키 중복 합산 (P2)

- `workplace_monthly`에 넣기 전에 자연키 `(biz_no6, name_norm, workplace_name, legal_dong_code)`로 묶는다.
  - `members` · `billed_amount` · `new_members` · `lost_members`: 합
  - `joined_on`: 가장 이른 값
  - 상태: 묶음 안에 등록 행이 하나라도 있으면 등록
- 13개월 모두 합산 전후 `members` 합계가 같다. 합산으로 줄어드는 행은 매달 45~49행이다.
- `uk_wp(company_id, workplace_name, legal_dong_code)`는 그대로 둔다. 합산 뒤에는 중복이 없다.
