## 5. 주소 상세 수준 (02 문서 8.2-10)

| 주소 | 수준 | 행 |
|---|---|---|
| 도로명 | 도로명까지 (`…독서당로14길`) | 568,498 (96.19%) |
| 도로명 | 빈 값 | 22,499 (3.81%) |
| 도로명 | 도로명보다 넓음 (`…시계탑거리`) | 31 (0.01%) |
| 도로명 | **건물번호 있음** | **0** |
| 지번 | 읍면동까지 (`…한남동`), 번지 없음 | 590,951 (99.99%) |

**결론: 건물 단위 좌표를 얻을 수 없다.** Phase 8 회사 좌표는 SPEC Phase 1-2대로 `accuracy`를 `road` 또는 `dong`으로 저장하고, 화면은 "대략 위치"로 표시한다(FR-MAP-06, DR-09).

제안(팀장 결정 필요):

1. **`road`:** 주소정보누리집 검색 API에 "시군구 + 도로명"을 넣어 같은 도로의 건물 목록을 받고, 그 좌표들의 중앙값을 쓴다. 긴 도로는 수 km라 오차가 크다.
2. **`dong`:** `legal_dong_code`로 법정동 경계 공개 데이터의 중심점을 쓴다. 호출이 필요 없고, 코드가 모든 행에 있다.
3. 권장: 2(`dong`)를 기본으로 전체에 먼저 적용하고, 지도 대상 상위 회사만 1(`road`)로 올린다. juso 호출 한도를 아낀다.

## 7. 발견한 문제와 제안

| # | 영향 | 문제 | 제안 | 관련 Task |
|---|---|---|---|---|
| P1 | **높음** | SPEC 품질 검사 "`members ≤ 0`이면 `failed`"를 행 단위로 적용하면 **모든 월이 실패**한다. 매달 탈퇴 사업장 약 3.8만 행이 0명으로 들어 있다 | 탈퇴(`status_code=2`) 행은 raw에만 보존하고 `workplace_monthly`에 넣지 않는다. 품질 검사는 "등록 상태인데 `members ≤ 0`인 행이 전체의 1% 초과"처럼 비율로 바꾼다(현재 0.10%) | T2-02, T1-04 |
| P2 | 중간 | 사업장 자연키(회사 + 사업장명 + 법정동)가 같은 행이 181묶음 있다. 예: 같은 회사 · 같은 동에 적용일자가 다른 사업장 2개. 그대로 UPSERT하면 한 행이 다른 행을 덮어써 가입자가 사라진다 | 적재 때 자연키로 묶어 `members` · `billed_amount` · `new` · `lost`를 합산한다. 적용일자는 가장 이른 값. `joined_on`을 키에 넣어도 73행이 남아 합산이 단순하다 | T1-04, T2-01 |
| P3 | 중간 | 시도 코드가 개편 중이다. 광주 · 전남은 `12 전남광주통합특별시` 하나로만 나오고(옛 29 · 46 없음), 강원(42 · 51)과 전북(45 · 52)은 옛 코드와 새 코드가 함께 있다. 월마다 같은 사업장의 `legal_dong_code`가 바뀌면 자연키가 달라져 이력이 끊긴다 | 과거 월 파일을 받으면 같은 사업장의 코드가 바뀌는지 확인한다. `region` 기준표는 옛 코드와 새 코드를 모두 담는다 | T1-01, T2-01 |
| P4 | 낮음 | 한자만 있는 상호는 `normalize_name` 결과가 빈 문자열이다(1행) | 결과가 비면 원래 상호에서 공백만 뺀 값을 쓴다. SPEC 6장 함수 수정이 필요하므로 팀 합의 후 반영 | T1-04 |
| P5 | 확인 필요 | **과거 월 파일 확보 범위를 아직 모른다.** 지금은 2026-08 한 달뿐이다. SPEC은 13개월 백필을 전제로 한다 | 공공데이터포털 "국민연금공단_국민연금 가입 사업장 내역"의 이전 버전 파일 목록을 확인한다. 13개월이 안 되면 팀장에게 알리고 `short_history` 기준을 다시 본다 | T1-01 |
