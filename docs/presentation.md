## 5. 설계

- **3계층 DB:** raw(받은 그대로) → core(정규화 · 좌표) → mart(미리 집계). API는 mart만 읽는다. 규칙이 바뀌면 raw에서 다시 만든다.
- **멱등 적재:** 같은 파일은 체크섬으로 건너뛰고, 같은 행은 `row_hash` · `ON DUPLICATE KEY UPDATE`.
- **품질 검사:** 전월 대비 행 수 ±10%, 가입자 0명 비율 등에 걸리면 `failed`로 남기고 mart를 갱신하지 않는다.
- 그림: README의 시스템 구조(mermaid)

## 6. 확장판 ★: 배포 · 회사 매칭 · 회사 좌표

**배포** (runbook 4장, 06 문서 3장)
- 월 갱신은 로컬에서: 국민연금 파일 받기 → 서울 · 성남 추출 → 적재 → 품질 검사 확인 → mart 갱신(48초, 한 트랜잭션) → 덤프 · 테이블로 배포 DB에 반영.

**회사 매칭** (matching.md)
1. 정확: 사업자번호 앞 6자리와 정규화한 이름이 모두 같다(14,854건)
2. 유사: 같은 6자리 안에서 이름 유사도 85점 이상(136건). "LG디스플레이 ↔ 엘지디스플레이(주)"처럼 영문은 한글로 읽고 비교
3. 그 외는 잇지 않는다. 방식과 점수는 늘 기록하고, 유사 연결은 화면에 "이름 기준 연결"로 표시
- 가입자 1,000명 이상 회사 79.3%(344 / 434, 성남 34 / 42), 서울 본사 상장사 69.1%(972 / 1,406)
- 규칙으로 안 되는 큰 회사는 수동 연결로 기록: 네이버(DART "NAVER"), 판교 SK(주)(지점 사업자번호)

**회사 좌표 4단계** (validation.md, decisions/004)
- DART 본사 주소 → 상위 300곳 상호 검색 → 도로 중심 → 동 중심
- 건물 11,961곳 · 도로 중심 112,867곳 · 동 중심 1,579곳. 대략 위치는 점선 핀(본사 대비 거리 중앙값 도로 305m · 동 567m)
- 좌표 API 2.6만 회(약 4.5시간 예상) 대신 주소 출입구 파일로 계산해 16초

## 7. 핵심 SQL

**① 빈 달이 있는 시계열**
- 퇴사율 = 상실자 ÷ **직전 달** 가입자. 회사가 한 달 빠지면 `LAG`는 두 달 전 값을 가져온다.
- 직전 행이 정말 직전 달일 때만 계산하고 아니면 NULL. 그래프도 그 달에서 선을 끊는다.

```sql
CASE WHEN LAG(snapshot_ym) OVER w = PERIOD_ADD(snapshot_ym, -1)
     THEN lost / NULLIF(LAG(members) OVER w, 0) END AS quit_rate
```

**② 업종 안 백분위와 표본 부족**
- 서울 · 성남 회사의 60.7%가 가입자 10명 미만이다. 한두 명만 나가도 퇴사율 50%라 분포에 넣으면 큰 회사의 백분위가 흔들린다.
- 표본 부족 회사는 따로 나눠 백분위를 NULL로 두고, 화면에 "가입자가 10명 미만이라 크게 흔들릴 수 있습니다"를 붙인다.

```sql
PERCENT_RANK() OVER (
  PARTITION BY industry_code, quit_rate_12m IS NULL OR small
  ORDER BY quit_rate_12m)
```

**③ 역세권 공간 조인** (explain.md 3장, TS-025)
- 역 500 · 750m 안 건물의 원룸 계약으로 시세를 낸다. 공간 조인을 윈도 함수 쿼리 안에 넣자 MariaDB 11.4가 공간 인덱스를 버렸다.
- 역-건물 쌍을 먼저 만든다(q5a): 기간 하나 320초 → 0.9초, mart 전체 갱신 5분+ → 48초.
- 회사 근처 역(1km)은 숫자 좌표라 공간 인덱스가 없어 위도 · 경도 범위로 먼저 거른다: 284초 → 5.6초.

```sql
INSERT INTO station_building
SELECT st.station_id, b.building_id, ST_Distance_Sphere(st.pt, b.pt)
FROM station st STRAIGHT_JOIN building b
  ON MBRContains(ST_Buffer(st.pt, 0.009), b.pt)
 AND ST_Distance_Sphere(st.pt, b.pt) <= 750
```

**④ 확장판 ★: 역세권 반경 500 · 750m** (decisions/009)
- 강남역 12개월 월세 계약 437 → 1,215건, 시세가 있는 역 293 → 303곳(기준월 2026-08).
- 지도에 두 원을 그려 집계 범위를 보여 준다. 1km는 이웃 역과 겹쳐 하지 않았다.

## 9. 시연 순서

1. 지도 메인: 핀 지표 바꾸기(증감 → 퇴사율 → 연봉), 목록 10 · 20곳씩 페이지
2. "우아한형제들" 검색 → 상세: 결과표, 근처 역 주거비, 채용 사이트 바로가기
3. 비교에 담기 3곳 → 가입자 지수 그래프
4. 지역 "관악구" → 역 "신림" → 반경 500 → 750m(지도에 두 원)
5. 역 3곳 담기 → 역 비교(지도가 세 역에 맞춰짐)
6. 지역 "성남시 분당구" → 판교역 시세, "네이버" 검색 → 근처 주거비(성남 확장)
7. 점선 핀 → "대략 위치" 안내

단계마다 화면에 나와야 할 값, 전날 점검, 비상 계획(로컬 서버 · 녹화 영상 · PDF)은 [demo.md](./demo.md).

## 10. 확장판 ★: 트러블슈팅 (troubleshooting.md TS-001 ~ 032)

| 주제 | 무엇이 문제였나 | 어떻게 풀었나 |
|---|---|---|
| 생성 컬럼(1901) | MariaDB는 `CHAR` 원본의 생성 컬럼을 거부 | 원본을 `VARCHAR`로, 생성 컬럼 + 일반 인덱스 |
| 공간 인덱스(TS-025) | 윈도 함수 안 공간 조인이 인덱스를 안 씀 | 쌍을 먼저 만들기, 좌표 범위로 먼저 거르기 |
| 임시 테이블(TS-028) | 750m를 더하자 16MB를 넘어 디스크로, 10분 | 이 연결의 한도를 256MB로, 다시 0.9초 |
| 대표 사업장 중복 | 모든 사업장으로 회사-역 순위 → 같은 역이 겹쳐 1순위가 사라짐 | 회사마다 대표 좌표 하나로만 순위 |
| 좌표 API(TS-022) | 몰아 부르면 오류를 정상 응답으로 줘 실패로 캐시됨 | 일시 오류는 캐시 안 함 → 결국 주소 파일로 16초 |
| 전각 괄호(TS-016) | "（주）"가 정규화되지 않아 같은 회사가 둘로 | NFKC 정규화 뒤 다시 만듦 |

## 12. 테스트 · 보안 · 일한 방식

- **CI 세 작업:** 테스트 · 웹(lint · 타입 · 빌드 · 화면) · API 이미지. 릴리스 `v1.0.0` ~ `v1.3.0`.

## 13. 한계와 마무리

- 추정 연봉은 회사 평균의 하한이다. 개인 · 직무별 연봉이 아니다.
