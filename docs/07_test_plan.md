## 1. 목표와 범위

- **목표:** 마감(10/21) 전에 배포된 서비스가 요구사항대로 동작하는지 확인하고, 남은 문제의 우선순위를 정한다.
- **범위:** 데이터 파이프라인(적재 · 품질 검사 · mart), API 13개 경로, 웹 화면(지도 메인 · 검색 · 상세 · 비교 · 역 시세 · 역 비교 · 계산 방법), 배포(Railway · Vercel).
- **범위 밖:** 하지 않기로 한 기능(FR-JOB-01 ~ 05, FR-SRCH-07, FR-DATA-09 채용 연계, decisions/008)과 P3(FR-X-01 ~ 08). 부하 테스트는 이미 한 결과([performance.md](./performance.md))를 쓴다.

## 9. 다시 돌리는 방법

```bash
ruff check . && python -P -m pytest               # 232개
cd web && npm run lint && npm run typecheck && npm run test:e2e && npm run test:e2e:map   # 8 + 6개
```

배포 API 점검은 경로마다 기대 상태 코드와 필수 필드를 적은 표로 요청을 보내고 응답 시간을 잰다(09 문서 2장의 26개 요청). 데이터를 바꿨으면 브라우저 캐시(최대 1시간)를 비우고 본다(runbook 4장).
