## 대표 사례

| 문제 | 원인 | 해결 | 재발 방지 | 기록 |
|---|---|---|---|---|
| 역세권 시세 집계가 기간 하나에 약 5분 | 공간 조인을 윈도 함수와 한 쿼리에 넣으면 MariaDB 11.4가 공간 인덱스를 쓰지 않음 | 역-건물 쌍을 임시 테이블로 먼저 만들고 그 쌍으로 백분위 → 0.9초 | 공간 조인은 윈도 함수와 한 쿼리에 넣지 않는다는 규칙, 실행 계획 테스트 | TS-025 |
| 반경 750m를 더하자 집계 10분 이상 | 임시 테이블이 16MB 기본 한도를 넘어 디스크로 내려감 | 이 연결에서만 한도 256MB → 1초 안 | 집계 대상이 늘면 mart 갱신 시간을 다시 잼 | TS-028 |
| 좌표 API 실패가 캐시됨 | 몰아 부르면 오류를 정상 응답 모양으로 돌려줌 | 일시 오류는 캐시하지 않음 → 결국 주소 파일로 직접 계산(16초) | 본문 안 오류 코드를 나눠 다루고, 대량 실행 전 수십 건으로 성공률 확인 | TS-022 |
| 같은 회사가 둘로 나뉨 | 전각 괄호 "（주）"가 정규화되지 않음 | NFKC 정규화 뒤 다시 만듦 | 외부 문자열은 키로 쓰기 전에 NFKC | TS-016 |
| 마곡역이 눌리지 않음 | 원본 역 자료에 다른 역(발산) 좌표가 들어가 두 역이 겹침 | 가까운 다른 이름 역은 주소로 다시 계산해 고침 | 단위 테스트, 적재 로그 확인 | TS-033 |
| 업종 분류 없는 회사에 업종 판정이 나옴 | 업종 코드 999999에 서로 다른 업종이 섞여 한 분포로 계산 | 999999는 업종 백분위에서 제외 | SQL 회귀 · 화면 테스트 추가 | TS-034, I-01 |
| 계산 방법 API만 약 2초 | 월별 mart에 월 인덱스가 없어 전체 스캔 | 마이그레이션 0011로 월 인덱스 → 약 0.24초 | 인덱스 존재 테스트 | I-02 |
