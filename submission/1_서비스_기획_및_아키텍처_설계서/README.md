## 핵심 설계 의도 (요약)

| 설계 | 이유 |
|---|---|
| **raw → core → mart 3계층 DB** | 원본을 보존해 계산 규칙이 바뀌면 다시 만들 수 있고, API는 미리 집계한 mart만 읽어 요청 때 집계하지 않는다(상세 p95 8ms) |
| **통계는 SQL로** | 윈도 함수 · `PERCENTILE_CONT` · 공간 인덱스로 DB 안에서 계산하고, SQL 파일을 회귀 테스트로 고정한다 |
| **사업자번호 6자리 + 정규화 이름으로 회사 식별** | 출처 사이에 공통 키가 없다. DART와는 정확 → 유사(85점 이상) → 그 외 연결 안 함 순서로 잇고 방식 · 점수를 기록한다 |
| **좌표는 주소정보누리집 것만 저장** | 이용 조건상 저장이 허용된 좌표만 쓴다. 건물번호 없는 주소는 도로 · 동 중심으로 두고 화면에 "대략 위치"로 표시한다 |
| **추정치에 `flags` · 기준월 `as_of`** | 표본 부족 · 하한 추정 · 대략 위치를 숫자와 함께 알려 과신하지 않게 한다 |
| **로컬 적재 → 배포는 읽기만** | 국민연금 파일을 자동으로 받을 수 없어, 로컬에서 적재 · 품질 검사한 결과만 배포 DB에 올린다 |
| **지도 메인 + 왼쪽 패널** | 회사를 주변 회사와 함께 보는 것이 검색 사이트와 다른 점이다(decisions/006) |
| **채용공고는 바로가기** | 사람인 · 고용24가 개인에게 API를 주지 않고 크롤링은 하지 않는다(decisions/008) |
